# M1.7 review: adjustments contract

The user's adjustments after trying M1.7 in the browser (2026-10-23). They change approved rules (design D9, the M1.7c drugs-page rules, the chip cases); the user confirmed them. Coders and test writers both work from this file.

## R1. Drugs page: tree view and list view

- A second toggle on the drugs page, «طريقة العرض» / "View" (`ToggleButtonGroup`, `aria-label` = that text, exclusive): «شجرة» / "Tree" and «قائمة» / "List". i18n keys: `drugs.view.label`, `drugs.view.tree`, `drugs.view.list`.
- **Default: the tree.** URL query `view`: absent → tree; `view=list` → the flat list (today's table); any other value (`view=bogus`, `view=TREE`) is dropped silently → tree. The default is left out of the URL (`writeDrugListParams` writes `view=list` only). Clicking the already pressed button keeps it.
- Changing the view keeps the search, the source, the category and the subcategory; the list's `page` is reset to 1 (the tree has no page). Back/Forward and opening/closing a drug's dialog keep the view (URL, as the other filters).
- **One filter bar for both views:** the page's own search, source toggle «الكل» / «المشتركة» / «أدوية العيادة» and the category / subcategory selects drive both views. In the tree view the tree's own search box and source toggle are not shown (one search, one toggle on the page). The tree view uses the same `DrugTree` component as the pickers (categories → subcategories → drugs, infinite scroll, keyboard, auto-open of a lone bucket), fed by the page's state.
- **Category filters in the tree view:** a chosen category shows only that category's node, opened; a chosen subcategory (or «بدون تصنيف فرعي») shows only that subcategory under it, opened (its first page loaded). Clearing the filters shows the whole tree again.
- **Rows in the tree view** act like the list rows: no «مُضاف» chip, no ⊕ add affordance; a click (or Enter) on a drug opens the same dialog the list opens (own drug: edit with `drugs.update`, else details with `drugs.details`; shared drug: read-only details with `drugs.details`; without the permission the row doesn't open). Own drugs show ✎ / 🗑 under the same permissions as the list; shared drugs never do. The «معطّل من الإدارة» chip stays.
- The subtitle «إجمالي الأدوية: N» stays in both views (the number of drugs matching the current filters).
- Empty states are the list's: «لا توجد أدوية مطابقة للبحث.», «لا توجد أدوية خاصة بالعيادة بعد.» + «إضافة دواء», «لا توجد أدوية مطابقة للفلاتر.» + «مسح الفلاتر».
- «إضافة دواء» and saving an own drug work in both views (the C35 rule: saved while «المشتركة» is chosen → «أدوية العيادة», search cleared; the view is kept). The tree refreshes after a save or delete.
- Phone (375 px) and Arabic (RTL): the view toggle wraps with the filters, nothing overflows or is cut.

## R2. No «مشترك» / "Shared" chip anywhere

- Never show the «مشترك» / "Shared" chip: drugs page (both views), the drug tree in the prescription page and in the protocol editor, protocol cards and lines, prescription lines.
- Own drugs keep the «خاص بالعيادة» / "Clinic" chip. The «معطّل من الإدارة» chip and «مُضاف» are unchanged.
- The source toggle button «المشتركة» / "Shared" (`drugs.source.shared`) stays; only the row chip goes. The key `drugs.chip.shared` is removed from `en.ts` and `ar.ts`.

## R3. A search opens single-drug branches by themselves

- In the drug tree (prescription page, protocol editor, drugs page tree view): on the first answer of a search, every category that has exactly one subcategory holding exactly one drug opens, with that subcategory, so the drug shows without a click. Pure helper `singleDrugBuckets(tree)` in `drugTreeModel.ts`.
- Only with a search typed (not the empty tree, nor a source or category filter alone). The lone-bucket rule (D7) is unchanged and applies as before. A category with one subcategory of 2+ drugs, or 2+ subcategories, stays closed. A branch the user closes stays closed until the search changes (as D7).

## R4. The drug tree's look

Visual only (no behavior, roles, names or texts change), in the tree everywhere (prescription, protocol editor, drugs page):
- Each category row starts with a pictogram tile for its category (`categoryIcons.tsx`, by the 23 catalog ids; any other id gets a generic icon; `aria-hidden`), tinted when closed and filled with the primary color when open; the chevron sits at the row's end. Subcategory rows keep the chevron at their start (left/right/down as before).
- Counts are small pills with tabular digits, tinted when their node is open.
- A thin guide line (the divider color) ties an open category to its subcategories and an open subcategory to its drugs.
- An open category's row stays pinned at the top of the tree panel while its drugs scroll; rows scrolled into view by the keyboard stop below it (`scroll-margin-top`).
- In the pickers, ⊕ is a round outlined target that fills on hover; «مُضاف» is unchanged.
