## 1. Goal

The platform ships with a **shared drug catalog** of the Egyptian market (23,414 drugs), classified
in **categories and subcategories**, that only the super admin changes and every clinic uses as if it were its own.
Clinics keep adding their own drugs. Groups are renamed **protocols**.

**Done when:** a clinic owner types "amoxicillin" in the prescription page and sees «مضادات العدوى › البنسلينات» open by
itself with its 203 shared matches (and the clinic's own, each with its chip); adds a shared drug and an own drug to a
protocol, adds the protocol to a prescription and copies it; the super admin edits that shared drug's name and every
clinic sees the new name at its next load.

## 2. Business (summary; full rules in the [business file](m1.7-shared-catalog.business.md))

| Area | Rule |
|---|---|
| **Shared drugs** | Platform-wide, imported once. Only the super admin adds, edits, disables and enables them (code: withdraw / restore) (admin area). Clinics see and use them everywhere but can't change them. No default dosing. Never deleted: **withdrawn** instead, shown as «معطّل من الإدارة» / "Disabled by admin" with a tooltip (hidden from lists, search and the tree, kept in protocols with the mark, can be enabled again). The 1,648 source rows marked not for sale are not loaded. Only the English name is ever shown; the source's Arabic name is an internal column, never exposed (D3) |
| **Own drugs** | As today (name, description, default dosing, delete removes it from every protocol) + a **required category**, an optional subcategory and optional active ingredients. One name, typed in English or Arabic as today (no separate Arabic name). Only that clinic sees them |
| **Same everywhere** | Search, the tree, protocols and prescriptions treat shared and own drugs the same way. The drugs page tells them apart: a chip on every row and an **All / Shared / Clinic's own** toggle. Own drugs come first (newest first when nothing is searched; with a search, names starting with the term first, then A→Z) |
| **Categories** | Two levels, shared by the platform, names in Arabic and English (shown in the UI language). Super admin: create, rename, delete; delete only when no drug (shared, withdrawn, or any clinic's own) uses it. Every drug has a category; a drug without a subcategory shows under «بدون تصنيف فرعي». «أخرى» and «غير مصنف» are always listed last |
| **Tree** | Categories → subcategories (match counts, a total above) → drugs, loaded 30 at a time while scrolling, in the prescription page and the protocol editor. The search also matches category and subcategory names |
| **Protocols** | "Groups" renamed everywhere: UI ("Protocols" / «البروتوكولات»), routes, API, tables, permissions. Behavior unchanged, plus the withdrawn-drug rules (a protocol's drug disabled by admin is still added to a prescription, with a warning) |
| **Import** | One time, by one Python script (D11); a clean database built with it becomes the production baseline, kept from then on (migrations preserve data) |

**Out of scope (M1.7):** drug interactions and same-ingredient warnings (separate feature, maybe never); per-clinic
overrides of shared drugs (own default dosing, hide, favorite); a re-import pipeline; prices; clinics creating categories;
moving a subcategory to another category; manual category order; open tree nodes remembered between visits.

## 4. Decisions

### D1. One `Drugs` table; `ClinicId` null = shared

- **Context:** shared drugs must behave exactly like own drugs everywhere except the drugs page and the write rules.
- **Decision:** shared drugs are rows of `Drugs` with `ClinicId = null`. A new marker interface
  `IClinicOrShared` (Domain/Common, `int? ClinicId`) replaces `IClinicOwned` on `Drug` only. Its query filter
  (a new generic next to `ConfigureClinicOwned`): `x.ClinicId == null || (ClinicId != null && x.ClinicId == ClinicId)`:
  a clinic request sees the shared drugs + its own; a **platform** request (no clinic) sees **only the shared drugs**,
  which is what the admin catalog screens need. `IgnoreQueryFilters()` on `Drugs` stays limited to Platform code.
- **Why:** protocol lines keep one `DrugId`; one query, one ordering, one paging for every list; the duplicate-line rules
  keep working; the drug id stays globally unique.
- **Not taken:** two tables (`SharedDrugs` + `Drugs`; every line needs two nullable FKs + "exactly one", search merges
  two queries, the SPA must carry a "kind" next to every drug id because ids collide); copying shared drugs into each
  clinic (storage per clinic, updates never reach clinics: the reason for this feature).
- **Cost:** the composite FK `(DrugId, ClinicId)` from protocol items can't point at a shared row (D4 replaces it).
  Browser prescription snapshots get a narrower type (D9) so old stored lines keep working.

### D2. Writes: shared rows only through the admin catalog use cases

- **Flag:** `IClinicContext` gets `bool WritingSharedCatalog`; `IClinicScope` gets `IDisposable UseSharedCatalog()`
  (no new service). It sets the flag for a block and restores it on dispose (nestable). It **throws** when a clinic is in
  context, and `Use(clinicId)` / `EnterAsync` inside it throw (a request never mixes the two). `AppDbContext` exposes
  `IsWritingSharedCatalog` (read from `IClinicContext`, like `ClinicId`) to the singleton interceptor. Only the admin
  catalog handlers (D8) call it, so provisioning, the dev seed or a buggy handler can't create a shared drug by
  forgetting a clinic.
- **Interceptor** (`ClinicAndTimestampsInterceptor`) for `IClinicOrShared`:

  | Row | Clinic context | No clinic context |
  |---|---|---|
  | Added, `ClinicId` 0/null | stamped with the current clinic (an own drug) | stays shared **only inside `UseSharedCatalog()`**, else throws |
  | Added/Modified/Deleted, own row | as `IClinicOwned` today (same clinic only) | throws |
  | Modified, shared row | **throws** (a clinic can never change a shared row, whatever the handler does) | allowed only inside `UseSharedCatalog()` |
  | Deleted, shared row | throws | **throws, even inside `UseSharedCatalog()`** (shared drugs are withdrawn, never deleted) |
  | `ClinicId` changed (shared ↔ own, or clinic → clinic) | throws | throws, even inside `UseSharedCatalog()` |
  | `Drug` added or modified: a shared row with any `DefaultDosing_*` set, or an own row with `IsWithdrawn` | throws | throws |

- With the handlers, the interceptor is the **only** guard on drug rows: there is no database trigger and no check
  constraint (D4). The last row is the one `Drug`-specific rule of the interceptor ("shared ⇒ no dosing", "own ⇒
  never withdrawn"). `IsWithdrawn` and `WithdrawnAt` change together only through `Drug.Withdraw(at)` /
  `Drug.Restore()` (private setters). The load script (D11) is outside the app: it writes no dosing and no withdrawn
  row.
- **Clinic use cases** (`UpdateDrug`, `DeleteDrug`) look the drug up through the filter (a shared drug **is found**),
  then answer **409 `sharedDrugReadOnly`** for a shared one, at the end of their checks (order in § 7).
  `GetDrugProtocolNames` (ex `GetDrugGroupNames`) works for both.
- `Categories` and `SubCategories` are **not** clinic-owned (platform rows, no `ClinicId`); clinic use cases only read
  them. Their writes happen only in admin handlers (`PlatformAdmin` policy).
- No `ExecuteUpdate`/`ExecuteDelete` or raw SQL writes `Drugs`, `Categories` or `SubCategories` outside the admin
  handlers, migrations and the test harness (they bypass the interceptor; an architecture test checks it), and no
  `ExecuteUpdate` anywhere in the app sets a searched text (a drug's `Name`, `NameAr` or `ActiveIngredients`, a
  protocol's or a clinic's `Name`, a staff member's `FullName`): it would leave the search columns stale (D7). Direct
  SQL edits of the database are not guarded (§ 6).

### D3. Drug fields

| Field | Shared | Own | Rule |
|---|---|---|---|
| `Name` | the source's full English name, whitespace normalized ("ALEMOX 1 GM 12 F.C.TABS."); the only name ever shown | as typed (English or Arabic, as today) | required, ≤ 256, `ValidName()`; not unique |
| `NameAr` (new) | the source's Arabic name («أليموكس»): an **internal column used only by search**, never exposed | always null (no field) | in no API body, DTO, screen (clinic or admin) or user text: only the load script writes it. An admin update whose `Name` differs from the stored one (ordinal, after trimming) **clears it** (null), and the same save refolds `SearchOther` (D7), so the drug no longer matches its old Arabic name; an update keeping the name keeps it |
| `ActiveIngredients` (new) | the source's `scientificName` ("AMOXICILLIN"), null for 2,286 rows | optional | new `SingleLineText(1000)` rule: no control characters (line breaks and tabs included) → `invalidText`; > 1,000 characters once trimmed → `textTooLong` (field `activeIngredients`); blank → null |
| `CategoryId` (new) | from the source | **required** | an existing category (`categoryRequired`, `categoryNotFound`) |
| `SubCategoryId` (new) | from the source (every imported drug has one); optional for an admin-created drug | optional | when given: an existing subcategory **of that category** (`subCategoryNotFound`) |
| `Description` | optional (admin); none imported | as today | `ValidText()` |
| `DefaultDosing` | **always null** (the admin API has no field; interceptor, D2) | as today | |
| `IsWithdrawn`, `WithdrawnAt` (new) | D6 | always false / null (interceptor, D2) | |

Not kept from the source: price (user's decision), manufacturer, route, the `ingredients` codes (they belong to the
interactions work). `(ClinicId, Name)` stays the ordering index;
new index `(CategoryId, SubCategoryId)`. A `("Name", "Id")` index is added only if the measure of D7 asks for it (each
page sorts the ~23K visible rows: about 10–20 ms).

### D4. Protocol lines and the guards

- **Principle (user):** M1.7 adds **no PostgreSQL-only piece to the app** (it may run on another database later): no
  trigger, no check constraint, no PostgreSQL function and no database-computed column in the schema. It also removes
  the one the app had: the `SearchName` generated columns become ordinary columns filled by the app (D7), so **search
  has no database-specific SQL**. Unchanged by M1.7: the Npgsql provider and the login lock (`pg_advisory_xact_lock`
  in `OtpLock`). The load script (D11) is outside the app and may use PostgreSQL features (`setval`).
- The `ProtocolItems` composite FK to `Drugs` (`FK_ProtocolItems_Drugs_DrugId_ClinicId` after the rename) is dropped,
  then the `Drugs` alternate key `AK_Drugs_Id_ClinicId` is removed (EF makes key columns required, so `ClinicId` can't
  become nullable while it exists). `Protocols` keeps its alternate key for the protocol FK.
- `ProtocolItems.DrugId` → `Drugs.Id`, **simple FK, cascade** (an own drug's delete removes its lines; shared drugs are
  never deleted). The protocol FK stays composite `(ProtocolId, ClinicId)`.
- **Guards, all in the app:**
  - A protocol line on another clinic's drug (the guard the composite FK gave): the protocol handlers (create and
    update) look every line's drug up through the clinic query filter, so another clinic's own drug isn't found →
    400 `drugNotFound`; a shared drug is found.
  - A drug changing owner (shared ↔ own, clinic → clinic), any change or delete of a shared row outside
    `UseSharedCatalog()`, any delete of a shared row, a dosing on a shared row, an own row marked withdrawn: the save
    interceptor (D2) throws.
- **Categories:** `CategoryId` → `Categories.Id` restrict; composite FK `(SubCategoryId, CategoryId)` →
  `SubCategories(Id, CategoryId)` restrict (a drug's subcategory always belongs to its category; MATCH SIMPLE skips it
  when `SubCategoryId` is null). Spiked first in M1.7b; fallback: a plain EF FK on `SubCategoryId` and the composite
  constraint added by `migrationBuilder.Sql` (standard SQL). A used (sub)category can't be deleted even by a bug.
- The test harness deletes its own test-created shared rows by raw SQL (D12): nothing in the database stops it.

### D5. Categories

```
Categories     Id, NameEn (≤100), NameAr (≤100), CreatedAt, UpdatedAt
SubCategories  Id, CategoryId (FK restrict), NameEn, NameAr, CreatedAt, UpdatedAt
               unique (Id, CategoryId) (the drugs' composite FK target)
```

- **Names:** both required, `ValidName(100)`, trimmed. Unique per language after trimming and `SearchText.Fold`
  (case, hamza and alef forms ignored): category names among categories, subcategory names within their category (two
  categories may each have "Other"). Checked in the handler against the ≤ ~200 names in memory; a rename to the row's own
  name (or another case or hamza of it) is allowed. → 409 `categoryNameTaken` / `subCategoryNameTaken` (field `nameEn`
  or `nameAr`). No unique index: a double submit racing past the check gives two rows or a 500, accepted (MVP rule).
- **Fixed ids:** ids follow `taxonomy.py`'s order and codes: categories 1–23, subcategories 1–182, mapped **by code**
  (`eye` → 17, `eye.glaucoma` → 138), never by English name. The migration creates the tables only; the rows are
  inserted by the one-time load script (D11), which then sets both identity sequences past them, so the first category
  the super admin creates gets id 24. `CategoryIds.Other` (23) and `SubCategoryIds.Unclassified` (182) are constants in
  Application.
- **Order:** the SPA sorts names with `Intl.Collator` in the UI language. «أخرى» / "Other" and «غير مصنف» /
  "Unclassified" are **pinned last** (the API returns `pinnedLast: true` for the two fixed ids: the pin is by id, so a
  rename keeps it and another category named "Other" isn't pinned);
  the «بدون تصنيف فرعي» / "No subcategory" bucket comes after them, last in its category. While a search is typed, the
  tree orders categories and subcategories by match count (largest first, ties by name), with the same pins. No manual
  order.
- **Delete:** a subcategory only when **no drug** uses it: shared (withdrawn included) **and every clinic's own drugs**,
  deleted clinics included (counted across clinics, `IgnoreQueryFilters()`, Platform code) → 409 `subCategoryInUse`
  with `drugCount`. A category only when no drug is in it (with or without a subcategory) → 409 `categoryInUse` with
  `drugCount`; its (empty) subcategories are deleted with it. Real deletes. A (sub)category used only by a deleted
  clinic's drugs stays blocked: the admin screen says how many of its drugs belong to deleted clinics.
- A subcategory **can't move** to another category (rename only): moving would break its drugs' category.
- Creating, renaming or deleting a subcategory never updates its category's row (no `UpdatedAt` touch on the parent):
  a test subcategory under an imported category leaves the imported rows unchanged (D12).
- **Existing data:** none is migrated. The dev database is reset before M1.7b (nothing is in production), then
  migrated and loaded by the script. `AddSharedCatalog` checks nothing: it assumes an empty `Drugs` table (on a
  database that still has drugs it fails and its transaction rolls back) and refolds no existing row (§ 5).
- **Clinic reads** (tree, filters, drug form): `GET /drug-categories` (permission `drugs.list`), `staleTime` 30 s like the
  pickers; the drug dialog refetches it when it opens.

### D6. Withdrawn shared drugs

| Where | Withdrawn shared drug |
|---|---|
| Clinic drugs page, tree, `GET /drugs`, `GET /drugs/tree` | **hidden** (never counted, never found by search) |
| `GET /drugs/{id}` | 200 with `withdrawn: true` (a protocol or an old tab may ask) |
| Protocol editor | the line stays, with the chip «معطّل من الإدارة» (tooltip) and the alert «بعض الأدوية عطّلها مدير المنصة في الكتالوج المشترك.» / "Some drugs were disabled by the platform admin in the shared catalog." above the lines; its ⊕ "add for the other eye" is hidden (it would add a second line); ✎, ✕ and drag work |
| Protocol save | a withdrawn drug's lines pass while **their number in the request ≤ its number of stored lines** in that protocol (any eye; dosing and eye may change). Beyond that (a second line, a line in a new protocol, a line removed and added back) → 400 `drugWithdrawn` on the first extra line (field `items[i].drugId`) |
| Protocol cards (protocols page, prescription tab) | «الأدوية: N» counts withdrawn lines too; the card adds «معطّل من الإدارة: N» (with the tooltip) when N > 0 |
| Adding a protocol to a prescription | its withdrawn lines are **added** like the others (an `ask` line asks its eye as usual), with a warning: each such prescription line carries the chip «معطّل من الإدارة» (tooltip; chip and tooltip on screen only, never copied), and a **second toast**, separate from the protocol toast, shown only when N > 0: «أُضيف رغم تعطيله من الإدارة: N» / "Added although disabled by admin: N" (`protocolWithdrawn`), plain (neutral) style with a ⚠ icon (`toast(text, { icon: "⚠️" })`: no new toast style), dismissible like every toast; the protocol toast itself is unchanged (its lines and its success/neutral rule: [prescription tech](../features/prescription/tech.md)) |
| Prescription lines already in the browser | unchanged (snapshots, as for edited or deleted drugs today): editable, ⊕ other eye works, copied |
| New clinic from the template | copied as they are (the template protocol keeps the line) |
| Super admin | admin drugs list: status filter «مفعّل» / «معطّل» / «الكل» (Enabled / Disabled / All); a withdrawn row carries the chip (tooltip); actions «تعطيل الدواء» / «تفعيل الدواء» ("Disable drug" / "Enable drug"; withdraw / restore: idempotent, 204), toasts «تم تعطيل الدواء» / «تم تفعيل الدواء» ("Drug disabled" / "Drug enabled") |

`IsWithdrawn` + `WithdrawnAt` (`TimeProvider`): a second withdraw keeps the first time; restore sets null; withdrawing
again sets the new time. An own drug is never withdrawn (`notFound` on the admin routes: the platform filter doesn't see
own drugs; the interceptor refuses an own row marked withdrawn, D2). **Words** (decided by the user, § 11 Q6): users see «معطّل من الإدارة» / "Disabled by admin" (never «مسحوب» nor «موقوف», which
suspended clinics use); the code keeps `withdrawn` (API, DB, keys). **Tooltip on every mark**: one shared chip component
(protocol editor line, protocol card count, prescription line, admin row) with the tooltip «عطّل مدير المنصة هذا الدواء في الكتالوج المشترك، فلا يظهر في البحث. يبقى في البروتوكولات التي تستخدمه.» /
"The platform admin disabled this drug in the shared catalog, so it no longer appears in search. It stays in the protocols that use it." It opens on hover, on keyboard focus (the chip is focusable, the text is also its accessible description)
and on tap (touch: no delay), closes on Esc or a tap elsewhere; screen only, never in the copied prescription text.

### D7. Search and the tree

- **Search columns filled by the app** (user, 2026-10-17; M1.7b). Every search column is an ordinary column
  (`text NOT NULL DEFAULT ''`), still an EF shadow property (domain entities don't carry it), filled in C# by the save
  interceptor: `SearchName` on `Drugs`, `Protocols`, `Clinics` (from `Name`) and `Staff` (from `FullName`), and the new
  `SearchOther` on `Drugs`. For every added or modified row of a searched table, `ClinicAndTimestampsInterceptor` sets
  each column from the row's current source text: `SearchName` = `SearchText.Fold(name)`; `SearchOther` =
  `SearchText.OtherText(nameAr, activeIngredients)` (the two joined by a space, null as empty, `+` and `(` → space, then
  `Fold`). The value only changes when its source text changed. The search folds the term with the same `SearchText`
  code (as today) and compares with `Contains`/`StartsWith`: one fold function on both sides, so they can't drift
  (today the database's `translate(lower())` must mirror the C# table). `HasSearchName(source)` and `HasSearchOther()`
  in `SearchNameConfiguration` declare the column and record its source properties in a model annotation that the
  interceptor reads: a new searched table needs one configuration line. `SearchText.OtherColumn` names the new column.
  **Search has no database-specific SQL.**
- Writes that skip the interceptor would leave a column stale: no `ExecuteUpdate` sets a searched text (architecture
  test, D2); a row inserted by raw SQL (a test, a hand edit) gets `''` and isn't found by search until the app saves it
  (accepted, like every direct SQL edit, § 6); the load script fills both columns of the imported rows itself (D11).
  Changing the fold table later needs a data migration that refolds the stored rows (`SearchTextTests` pins the
  table).
- `NameAr` is filled only on imported shared drugs, so an own drug's `SearchOther` holds its ingredients only; an admin
  rename clears `NameAr` (D3) and the same save refolds `SearchOther`.
- **Match:** a drug matches when the folded term is **contained** in its name (`SearchName`), its hidden Arabic name or
  its active ingredients (`SearchOther`), or the folded English or Arabic name of its category or subcategory
  ("glaucoma" or «المياه الزرقاء», the Glaucoma subcategory of Eye, shows its 91 drugs). The handler folds the ≤ 205
  category names in memory (`SearchText.Fold`, the same function as the columns) and adds the matching ids to the LINQ
  filter (`|| categoryIds.Contains(d.CategoryId) || subCategoryIds.Contains(d.SubCategoryId)`). The term compared with `SearchOther` gets the same `+`/`(` →
  space replacement (`SearchText.OtherTerm`), so a pasted "DEXAMETHASONE+TOBRAMYCIN" or "PARACETAMOL(ACETAMINOPHEN)"
  finds the drugs holding it.
- **Order**, the same for the drugs page list, the tree buckets and the admin list: **own drugs first, then shared**
  (the admin list holds shared drugs only). **With a search**, inside each part: names (`SearchName`) that **start
  with** the term first, then `Name` (A→Z, database collation), then `Id`. Nothing else ranks (no tier for the
  ingredients, the Arabic name or the category). **Without a search:** own drugs newest first (`CreatedAt`, then `Id`,
  both descending); then shared by `Name` (A→Z), then `Id`.
- **One query composition**, `DrugQueries.Listed(search, source, categoryId, subCategoryId)` (visible + not withdrawn +
  source + category filters + search), used by `GetDrugs` and `GetDrugTree`, so a bucket's count always equals the
  drugs it pages.
- **Tree** (`GET /drugs/tree?search=&source=`): one aggregate query: counts per `(CategoryId, SubCategoryId)`
  (`SubCategoryId` null = the «بدون تصنيف فرعي» bucket). Categories and subcategories with **0 matches are left out**
  (without a search too: an empty category isn't shown). Without a search the tree has all 23 categories and 182
  subcategories (every subcategory holds active drugs).
- **SPA:** a total «النتائج: N» above the tree (the sum of the category counts); categories collapsed, with counts →
  opening one shows **all** its subcategories with matches and counts (already in the answer: no request) → opening a
  subcategory loads `GET /drugs?categoryId=&subCategoryId=<id>|none` + the same `search`/`source`, 30 per page, the
  next page when the end of that list scrolls into view (`IntersectionObserver` whose root is the tree's scroll panel).
  Several subcategories may be open at once, each with its own query; closing one drops its pages, reopening starts
  from its first page. Rows are de-duplicated by id across pages.
- **Auto-open:** when the whole answer has exactly one subcategory bucket (a «بدون تصنيف فرعي» bucket included), it
  opens by itself; if the user closes it, it stays closed until the search changes.
- **New search:** debounced; the old tree stays with a thin progress bar until the new answer arrives, then the new tree
  replaces it with everything closed (an older, slower answer is ignored).
- **Source toggle in the tree** (All / Shared / Clinic's own) like the drugs page; changing it resets the tree
  like a new search.

### D8. API

### D11. One-time import and the production baseline

- **One script, run once per database:** `data/drug-catalog/tools/load_catalog.py --connection "<conninfo>"`
  (Python + psycopg; a libpq conninfo, `host=… port=… dbname=… user=… password=…`, built by the caller). It reads
  `drug-catalog.json` and `taxonomy.py` and, in **one transaction**: inserts the 23 categories and 182 subcategories
  with their fixed ids (D5) and the shared drugs (`Id` assigned by the identity; `ClinicId` null; search columns
  below); sets the `Categories` and `SubCategories` sequences past the fixed ids; runs `ANALYZE "Drugs"`. Used for dev (after a reset), the production baseline and to fill the test databases
  (D12); no generated SQL file, no other loader. "Load once and forget": the script is not tested and has no guards.
- **Rows:** 23,414 = the 25,067 source rows minus the second copy of the 5 names repeated with identical imported fields
  ("SIGMACYN 1500MG VIAL I.M. I.V.", "AVICHEST 5% SYRUP FOR ADULT 100ML", "HESSTA 50 MG CREAM", "SCAR NOT GEL 30 GM",
  "SEPTOLA LOZENGES 24 TAB HONEY AND LEMON") and minus the 1,648 rows marked "(N/A)", "(N/A YET)", "(CANCELLED)" or
  "(ILLEGAL IMPORT)" (not loaded at all; none is withdrawn after the load). Whitespace normalized in `Name`, `NameAr` and `ActiveIngredients`: every
  run of whitespace (line breaks and tabs included) → one space, trimmed ("CARBONECOL 30 H.G. CAPS\n." → "CARBONECOL 30
  H.G. CAPS .", "KLACID XL 500 MG  14 F.C.TABS." → one space); blank → null. After that, "CITICOLINE 500 MG 20
  CAPSULES" appears twice: two source products (two manufacturers, neither imported) whose names differed by a double
  space; identical on screen, both kept (accepted). `ActiveIngredients` =
  `scientificName`; `NameAr` = the source's Arabic name as stored (internal, search only, never exposed); `CreatedAt` = `UpdatedAt` = the import
  time.
- **Search columns:** the script fills them as the app's `SearchText` does (D7), on the normalized texts:
  `SearchName` = fold(`Name`); `SearchOther` = fold(`NameAr` + " " + `ActiveIngredients`, a null as empty, `+` and `(`
  → space). fold = lower case; أ إ آ ٱ and the superscript alef U+0670 → ا; ى → ي; ة → ه; ؤ → و; ئ → ي; the tatweel
  U+0640 and the diacritics U+064B–U+065F removed. Every loaded text is ASCII or Arabic (U+0600–U+06FF), where
  Python's `str.lower()` and .NET's `ToLowerInvariant()` agree. A change to `SearchText`'s table is mirrored here.
- **Check:** after each one-time load, the person running it checks the counts once by hand (23 categories, 182
  subcategories, 23,414 shared drugs, none withdrawn), and that's it.
- **Production baseline** (end of M1.7c, user present): drop and recreate `drags` **with the `en_US.utf8` collation** (as the
  compose database and the tests; tech overview § Known limitations: another collation, e.g. `C` or a Windows locale,
  changes the order of the 23K names: digits, Latin case, Latin before Arabic); `dotnet ef database update`; start the API once with `ASPNETCORE_ENVIRONMENT=Production` and the production settings (`Auth__Jwt__SigningKey`,
  `Otp__HashKey`, `Otp__Mode=Display` (the base `appsettings.json` holds `Sms`, which startup refuses),
  `Platform__SuperAdminPhones__0…`, the connection string; `MediatR:LicenseKey` is in `appsettings.json`) so only the template clinic and the super admins are seeded; stop it; run `load_catalog.py`; `pg_dump`
  → `drags-baseline-<date>.dump` kept outside git. From that moment the "nothing in production" rule ends: every
  migration keeps data (tech overview § Migrations). Dev work then uses a copy of the baseline + the dev seed.
- After the baseline the app never needs the script or the JSON; the tests still run them (D12). The script,
  `taxonomy.py` and the JSON are committed (user's decision); no test case is about them.

### D12. Tests carry the full catalog

- **Loading:** the integration harness and the e2e setup run `load_catalog.py` themselves, right after creating and
  migrating their database, with no shell (`Process.Start` with an argument list; `spawnSync` without `shell`), so
  Rider, `dotnet test`, `npm run e2e` and Stryker runs work the same as `test.ps1`. Python + psycopg become a test
  prerequisite (testing README): when missing, the harness and the setup stop with a message naming the install
  command; `test.ps1` only checks the prerequisite up front.
  - Integration: `TestRun.StartAsync` creates `drags_it_<run>_tpl` and boots the app on it as today (migrations +
    startup seeder), clears its pool, copies it to `drags_it_<run>_tpl_bare` (`CREATE DATABASE … TEMPLATE`, **before
    the load**), runs `python load_catalog.py --connection <tpl>`, then records the baseline. Both are this run's
    databases (dropped at shutdown, and by the stale cleanup like the others).
  - E2E: `global-setup.ts`, once the API answers (its startup created, migrated and seeded `drags_e2e_<run>`), runs
    `spawnSync("python", [script, "--connection", …])` on that database, then `seedTemplate`.
- **Integration:** the migration collection copies the bare template (migrated and seeded, no catalog) and runs
  without the baseline and checksum checks; the other collections copy the loaded one (`CREATE DATABASE … TEMPLATE`).
  PostgreSQL 17 copies with `STRATEGY = WAL_LOG`, a cost proportional to the size (~30–40 MB) × 28 collections:
  measured in M1.7b, `FILE_COPY` is the alternative. The harness records the **baseline**: max drug, category and
  subcategory ids, the shared count, and a checksum of the imported rows' contents:
  `md5(string_agg(t::text, ',' ORDER BY "Id"))` over shared `Drugs` (`Id` ≤ max), `Categories` and `SubCategories`
  (≤ their max ids).
- **Reset between classes:** Respawn with `TablesToIgnore` = `__EFMigrationsHistory`, `Clinics`, `Drugs`, `Categories`,
  `SubCategories` (Respawn's Postgres adapter runs `truncate … cascade`, and PostgreSQL cascades a truncate into every
  table that references a truncated one: `Clinics` must not be truncated or `Drugs` is emptied; none of the ignored tables
  references a truncated one). Then, in one transaction: `DELETE FROM "Drugs" WHERE "ClinicId" IS NOT NULL OR "Id" >
  @maxDrug` (cascades to any line left), `DELETE FROM "Clinics"`, `DELETE FROM "SubCategories" WHERE "Id" > @maxSub`,
  `DELETE FROM "Categories" WHERE "Id" > @maxCat`; then the checksum; then the startup seeder.
- **Checksum violation:** the check (`BaselineGuard.CheckAsync`) fails the run naming the class that just ran ("tests
  never edit imported rows or categories: create your own shared drug or category"); the collection database is
  re-created from the template so the next classes run clean; the collection fixture's dispose calls the same check (the
  last class). The harness self-tests call `BaselineGuard.CheckAsync` on a scratch copy they changed, never on the run's
  own database, so a normal run passes.
- **Test data:** real shared drugs are looked up by exact name (`Data.Shared("ALEMOX 1 GM 12 F.C.TABS.")`); tests that

  «المياه الزرقاء» ("Eye" › "Glaucoma").
- **E2E:** `global-setup.ts` loads the catalog into its `drags_e2e_<run>` (above); `seedTemplate` uses `/protocols`, looks categories up through `GET /drug-categories` and keeps its content (2 own drugs,
  now with categories, and 1 protocol: ADM-088 and `TemplateCatalog` expect them). Specs that write the shared catalog
  or categories form **their own Playwright project, which depends on the three browser projects and on
  `ar-desktop-template`** (so it runs last), with unique names and never imported rows.
  Clinic specs never assert global totals across loads: only "the subtitle equals the list's `totalCount`" within one
  load, or numbers read from the API. A count of the imported catalog (a search's, a category's or a subcategory's

- **Migration cases** (up → down → up, DRUG-101 and the M1.7 migration cases) run in the migration collection, on copies

  rows: the script loads them, D11); the new drug columns; the items' composite drug FK and `AK_Drugs_Id_ClinicId`

  (`text NOT NULL DEFAULT ''`) and `SearchOther` added as one. Whether EF emits `DROP EXPRESSION` or a drop and add,
  no existing row is refolded (the database is reset first). No trigger and no check constraint (D4). Its Down turns
  the four columns back into generated ones (PostgreSQL recomputes them; the SQL stays in that migration's history)
  and drops the rest; on a database holding shared drugs it fails on `ClinicId NOT NULL` and rolls back (not tested:
  nothing is in production).

Each is tested up → down → up with data (migration cases, in the migration collection on the bare template, D12).

## 6. Clinic isolation after M1.7

| Guard | Today | After |
|---|---|---|
| Query filter | own clinic only | own clinic **+ shared** for `Drugs`; unchanged for every other table |
| Save interceptor | clinic rows only | + D2 table (shared rows read-only in a clinic, never deleted; no dosing on shared rows; own rows never withdrawn) |
| Protocol line → drug | composite FK | `drugNotFound` in the protocol handlers (another clinic's drug isn't visible through the filter); no database guard |
| A drug changing owner | composite FK (used drugs) | the save interceptor (every drug, every context) |
| Platform requests | see nothing clinic-owned | see shared drugs + categories; own drugs only through explicit `IgnoreQueryFilters()` counts (category delete) |

**Direct SQL edits are not guarded** (accepted, MVP): every guard above lives in the app, so SQL run by hand on the
database (or by a tool outside the app) can write a cross-clinic protocol line, change a drug's owner or put a dosing on
a shared row. Nobody edits the database by hand; inside the app, raw SQL writes on these tables are limited by the
architecture test (D2).

Two clinics see the **same** shared rows: an edit by the super admin shows in every clinic on its next load (no cache).
No clinic can learn anything about another clinic: own drugs never appear in another clinic's lists, tree or counts, the
admin search never shows own drugs, and `drugCount` is visible only to the super admin (numbers, no names).

## 7. Errors (new and renamed)

| Code | Status | When |
|---|---|---|
| `sharedDrugReadOnly` | 409 | a clinic updates or deletes a shared drug (template context included) |
| `categoryRequired` | 400 | no `categoryId` (field `categoryId`) |
| `categoryNotFound` | 400 | `categoryId` doesn't exist (field `categoryId`) |
| `subCategoryNotFound` | 400 | `subCategoryId` doesn't exist **or isn't in that category** (field `subCategoryId`) |
| `invalidText` | 400 | `activeIngredients` with a control character or line break (field `activeIngredients`) |
| `textTooLong` | 400 | new common code: `activeIngredients` over 1,000 characters (field `activeIngredients`) |
| `drugWithdrawn` | 400 | a protocol save adds a withdrawn drug (field `items[i].drugId`, i = the line's index in the request) |
| `categoryNameTaken`, `subCategoryNameTaken` | 409 | a name already used (field `nameEn`/`nameAr`) |
| `categoryInUse`, `subCategoryInUse` | 409 | delete of a used (sub)category; body also has `drugCount` |
| `notFound` | 404 | admin routes: unknown or own drug id («The shared drug does not exist.»), unknown category or subcategory id |
| `invalidRequest` | 400 | an unknown `source`/`status`, a malformed `subCategoryId`, `subCategoryId` without `categoryId` |
| `duplicateProtocolItem` | 400 | renamed from `duplicateGroupItem` |

- **Where:** `CategoryErrors` in `Application/Features/Catalog/Categories` (shared by the clinic drug use cases and the
  admin ones); `SharedDrugErrors` in `Platform/SharedDrugs` (its `NotFound` text; `DrugErrors.NotFound` says "in this
  clinic"). `drugCount` travels in a new `Error` subclass `CountError` (`Application/Common/Results`, like `ClinicError`),
  a branch in `ApiProblemFactory.Create` adds the `drugCount` extension, and the SPA's `ApiError` reads it.
- **Order, drug create/update** (clinic and admin): validator (name → active ingredients → description →
  dosing (clinic only) → `categoryRequired`); then the handler: `categoryNotFound` → `subCategoryNotFound` → 404 (update)
  → `sharedDrugReadOnly` (clinic update). Delete: 404 → `sharedDrugReadOnly`. Database-backed 400s come before the 404,
  as for protocols (ISO-010).
- **Order, protocol save:** validator → `drugNotFound` → `drugWithdrawn` → `duplicateProtocolItem` → 404. The handler
  first counts the protocol's stored lines per drug (none for an unknown or another clinic's id, so every withdrawn
  line is extra there: 400, as ISO-010); a withdrawn drug's lines pass while their number in the request ≤ its stored
  count, and the first line beyond it gets `drugWithdrawn`.
- **Index of `drugWithdrawn`:** the handler keeps each line's request index through `SaveProtocolItem.Normalize` (nulls
  dropped, GRP-007); it is the first handler error with an index (the other protocol handler errors use field `Items`).
  The SPA names the drug from line i of what it sent (business message ««اسم الدواء» معطّل من الإدارة ولا يمكن إضافته.»).
- **Order, categories:** category create/rename: validator → name taken → 404 (rename). Subcategory create/rename:
  validator → 404 (category or subcategory) → name taken (uniqueness needs the row's category). Delete: 404 → in use.
- All codes get `errors.*` in `en.ts` and `ar.ts`.

## 8. Edge cases decided here

- **Order without a search:** own drugs first, newest first (`CreatedAt`, then `Id`, descending); then shared by name: the 11
  names with digits first ("1 2 3 (ONE TWO THREE) 20 F.C.TABS.", "2HC F.C.T 20 TABLETS"), then Latin (database collation,
  which ignores punctuation: "TOBRA-ALEX" before "TOBRABIOTIC"), then by id.
- **Same name twice:** after the import only "CITICOLINE 500 MG 20 CAPSULES" appears twice (two source products,
  identical on screen; accepted); a shared drug
  and an own drug may share a name: both listed (the own one first), told apart by the chip.
- **Own drug moved to another category** while in a protocol or a prescription: nothing else changes (lines point to
  the drug). Same for a shared drug moved by the super admin: it moves in every tree at the next load.
- **Super admin renames a shared drug** while a clinic has it in an open prescription: the prescription keeps the
  snapshot name until the line is re-added (existing rule); protocols show the new name at their next load, and saving an
  editor opened before the rename keeps the lines (200). The rename clears the drug's hidden Arabic name (D3): it is
  found by its new name, ingredients and category, no longer by its old Arabic name.
- **Category renamed or created** while a clinic's tree or form is open: shown at the next load (30 s `staleTime`, the
  drug dialog refetches on open); counts may be momentarily stale (accepted, like the pickers today).
- **Category deleted** while a clinic's drug form has it selected: save → `categoryNotFound` on the field; the form
  reloads the categories. A subcategory deleted between the check and the insert: the FK refuses it (500, nothing
  saved; accepted race).
- **Subcategory of another category** sent by a crafted request → `subCategoryNotFound`.
- **Withdrawn while in the protocol editor:** the open editor still shows it as normal; save keeps the line (it is a
  stored line, D6); the chip appears at the next load. Withdrawn between the check and the insert of a protocol save:
  the line is saved (accepted race; no constraint knows "withdrawn").
- **Withdrawn between opening the tree and clicking the drug** (prescription): the drug is added (snapshot of what was
  loaded; accepted, like stale pickers); in a protocol, save → `drugWithdrawn` only if it's a new line.
- **Template clinic** (super admin in the template context): shared drugs are read-only there too (edit them in
  `/admin/drugs`).
- **A clinic deleted** (soft): its own drugs stay and count in `drugCount`; a category used only by them can't be
  deleted (accepted: the admin screen shows how many belong to deleted clinics).
- **Two creates of the same category name at once:** two rows or a 500 (accepted, no unique index, D5).
- **Search term only matches the hidden Arabic name, an ingredient or the category:** found, ordered by name after the
  names starting with the term; the row shows the name and the ingredients (a category match is visible from the tree);
  a hidden Arabic-name match shows no reason on the row (accepted: the Arabic name is never exposed). `SearchOther`
  joins the Arabic name and the ingredients with a space, so a term spanning both also matches (harmless side effect,
  not specified).
- **Huge subcategories:** Multivitamins 1,469 drugs (49 pages of 30), Hair care 1,054, Topical pain relief 747;
  only open subcategories load, 30 at a time, inside the tree's scroll panel. The biggest category, «العناية بالبشرة
  والشعر», has 3,394 drugs.
- **A subcategory with 0 visible drugs for this clinic** but drugs in other clinics: hidden in this clinic's tree.
- **Names with characters that matter downstream:** `"` (13), `&` (213), `_` (2), `%` (1,399), `*` (154); `\` in none
  (an own drug may hold one): shown literally, escaped in the copied HTML, and matched literally by search (`%`, `_`,
  `\` escaped in LIKE).
