## 1. Spike results

### 1a. Composite subcategory FK: works natively in EF Core 9 + Npgsql (no fallback)

`DrugConfiguration`: `HasOne(Category).WithMany().HasForeignKey(CategoryId)` restrict, and
`HasOne(SubCategory).WithMany().HasForeignKey(new { SubCategoryId, CategoryId }).HasPrincipalKey(new { Id, CategoryId })`
restrict, with `SubCategoryId` `int?` and `CategoryId` `int` (the same column in two FKs); `SubCategoryConfiguration`
has the alternate key `AK_SubCategories_Id_CategoryId`. The scaffold is clean (`FK_Drugs_Categories_CategoryId`,
`FK_Drugs_SubCategories_SubCategoryId_CategoryId`, no warning). Proven on `drags_m17b_t0spike` (dropped):

| Statement | Result |
|---|---|
| insert a drug with category 1 and its subcategory 10 | ok |
| insert a drug with category 2 and no subcategory (MATCH SIMPLE) | ok |
| insert a drug with category 1 and subcategory 20 (of category 2) | **refused**: `FK_Drugs_SubCategories_SubCategoryId_CategoryId` |
| move a drug to category 2 keeping subcategory 10 | **refused** (same FK) |
| delete a used subcategory / a category holding subcategories | **refused** (restrict) |

Side effect, accepted: EF adds the FK index `IX_Drugs_SubCategoryId_CategoryId` next to the design's
`IX_Drugs_CategoryId_SubCategoryId` (two small indexes; the first serves the subcategory delete check). A subcategory's
`CategoryId` is part of its alternate key, so EF refuses to change it: the "can't move" rule (D5) holds by construction.

### 1b. Template copy cost: keep the default `WAL_LOG`

The loaded database (migrated + `load_catalog.py`: 23 categories, 182 subcategories, 23,414 drugs, loaded in ~2 s) is
**17 MB** (the design estimated 30–40 MB). `CREATE DATABASE x TEMPLATE y` on the compose PostgreSQL 17, 6 runs each:

| Template | `STRATEGY = WAL_LOG` (default) | `STRATEGY = FILE_COPY` |
|---|---|---|
| loaded (17 MB) | 55–101 ms (median ~64 ms) | 281–457 ms (median ~330 ms) |
| bare (7 MB, reference) | 28–46 ms (median ~37 ms) | — |

`FILE_COPY` forces two checkpoints per copy and is 5× slower here. ~28 collections × ~64 ms ≈ 1.8 s per run (+~0.8 s
compared with today's bare copies). **Recommendation: no change, `WAL_LOG` (the default).**

### 1c. The loader's numbers (checked once, D11)

23 categories, 182 subcategories, 23,414 shared drugs, none withdrawn, 2,286 without ingredients; `nextval` of the
category sequence after the load = 24; ids by code (`eye` → 17, `eye.glaucoma` → 138, `other` → 23,
`other.unclassified` → 182). Sanity search counts on the folded columns match the design: "amoxicillin" 203,
"tobra" 34, "moxi" 276.

### 2.2 EF model and migration `AddSharedCatalog`

- `AppDbContext`: `DbSet<Category> Categories`, `DbSet<SubCategory> SubCategories`; `bool IsWritingSharedCatalog`
  (reads `IClinicContext.WritingSharedCatalog`, for the singleton interceptor); `ConfigureClinicOrShared<T>` (FK to

- `DrugConfiguration`: `Name` ≤ 256 required, `NameAr` ≤ 256, `ActiveIngredients` ≤ 1000, indexes `(ClinicId, Name)`
  and `(CategoryId, SubCategoryId)`, `HasSearchName("Name")`, `HasSearchOther()`, the two FKs of § 1a.
  `AK_Drugs_Id_ClinicId` is gone.
- `ProtocolItemConfiguration`: the protocol FK stays composite `(ProtocolId, ClinicId)`; the drug FK is simple
  `DrugId → Drugs.Id`, **cascade**.
- `CategoryConfiguration` / `SubCategoryConfiguration`: names ≤ 100 required; `FK_SubCategories_Categories_CategoryId`
  restrict; `AK_SubCategories_Id_CategoryId`. No unique name index (D5).
- `SearchNameConfiguration`: `HasSearchName<T>(string sourceProperty)`, `HasSearchOther(this EntityTypeBuilder<Drug>)`,
  `SourceAnnotation = "ClinicHub:SearchSource"` (comma-separated source properties: `"Name"`, `"FullName"`,
  `"NameAr,ActiveIngredients"`), `SourcesOf(IReadOnlyProperty)`; each column is `.IsRequired().HasDefaultValue("")`.
  The old `Sql()` builder is removed (only `AddSearchNames` and its designer hold that SQL, as literals).

### 2.4 Errors (§ 7) and their order

| Code | Status | Declared in | Field | English description |
|---|---|---|---|---|
| `sharedDrugReadOnly` | 409 | `DrugErrors.SharedDrugReadOnly` | — | Shared drugs can't be changed by a clinic. |
| `categoryRequired` | 400 | `CategoryErrors.CategoryRequired` | `categoryId` | The category is required. |
| `categoryNotFound` | 400 | `CategoryErrors.CategoryNotFound` | `categoryId` | The category does not exist. |
| `subCategoryNotFound` | 400 | `CategoryErrors.SubCategoryNotFound` | `subCategoryId` | The subcategory does not exist in this category. |
| `invalidText` | 400 | `CommonErrors.InvalidText` | `activeIngredients` | (existing) |
| `textTooLong` | 400 | `CommonErrors.TextTooLong` | `activeIngredients` | The text is too long. |
| `drugWithdrawn` | 400 | `ProtocolErrors.DrugWithdrawn`, `DrugWithdrawnAt(int requestIndex)` | `items[i].drugId` | A drug of the protocol was withdrawn from the shared catalog. |
| `categoryNameTaken` | 409 | `CategoryErrors.NameTaken` (`with { Field = "NameEn" \| "NameAr" }`) | `nameEn` / `nameAr` | A category with this name already exists. |
| `subCategoryNameTaken` | 409 | `CategoryErrors.SubCategoryNameTaken` (field as above) | `nameEn` / `nameAr` | A subcategory with this name already exists in this category. |
| `categoryInUse` | 409 | `CategoryErrors.InUse`, sent as `new CountError(CategoryErrors.InUse, n)` | — | The category is used by drugs. (+ `drugCount`) |
| `subCategoryInUse` | 409 | `CategoryErrors.SubCategoryInUse` as a `CountError` | — | The subcategory is used by drugs. (+ `drugCount`) |
| `notFound` | 404 | `SharedDrugErrors.NotFound` («The shared drug does not exist.»), `CategoryErrors.NotFound` ("The category does not exist."), `CategoryErrors.SubCategoryMissing` ("The subcategory does not exist.") | — | |
| `invalidRequest` | 400 | `CommonErrors.InvalidRequest` (validators of the list queries) | `source` / `status` / `subCategoryId` | (existing) |

New error classes: `CategoryErrors` (`Application/Features/Catalog/Categories`), `SharedDrugErrors`
(`Application/Features/Platform/SharedDrugs`): name both in `docs/tech/overview.md` § Conventions and in
`ErrorCodeTextsTests.DocumentedClasses` (tests-api).

Order (§ 7), unchanged from the design:
- Drug create/update (clinic and admin): validator `name → activeIngredients → description → defaultDosing (clinic
  only) → categoryRequired`; handler `categoryNotFound → subCategoryNotFound → 404 (update) → sharedDrugReadOnly
  (clinic update)`. Clinic delete: `404 → sharedDrugReadOnly`.
- Protocol save: validator → `drugNotFound` → `drugWithdrawn` (first extra line, its request index through
  `SaveProtocolItem.Normalize`; nulls counted) → `duplicateProtocolItem` → 404.
- Category create/rename: validator → name taken → 404 (rename). Subcategory create/rename: validator → 404 →
  name taken. Delete: 404 → in use.
- Clinic list queries: `source` / `subCategoryId` validators → 400 `invalidRequest`; `categoryId` malformed → MVC
  binding 400 `invalidRequest`; unknown ids or a subcategory of another category → an empty page.
